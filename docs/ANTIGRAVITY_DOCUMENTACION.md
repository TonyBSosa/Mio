# Prompt listo para Antigravity

Trabaja en el proyecto MIO, ubicado en D:\VANGUARDIA\MIO. Lee primero las instrucciones aplicables y docs/PLAN_DE_TRABAJO.md. Nuestro entregable en ocho semanas es una aplicación para apartados, abonos y entregas de piezas únicas vendidas por pequeñas tiendas hondureñas en redes sociales. No aloja video. Conservaremos Angular, Express y MongoDB.

Tu tarea de esta sesión es documentación académica. Puedes leer el código fuente; escribe únicamente dentro de docs/academico/. No modifiques código, dependencias, configuraciones, otros documentos ni datos. No leas archivos de secretos, no publiques nada y no crees commits. Hay cambios de otra herramienta en el mismo workspace: no los reviertas.

Crea:
1. REQUISITOS.md: actores, problema, alcance, requisitos funcionales y no funcionales numerados, y criterios observables de aceptación.
2. CASOS_DE_USO.md: alta de pieza, apartado, consolidación por cliente, registro de abono, cancelación, entrega y consulta de saldo; flujo principal y errores relevantes.
3. MATRIZ_DE_TRAZABILIDAD.md: requisito → archivo existente cuando aplique → semana prevista → prueba propuesta.
4. PREGUNTAS_PARA_TIENDAS.md: entrevista breve para verificar el problema y acordar cancelaciones con dinero recibido, expiración y entrega.

En cada documento distingue claramente IMPLEMENTADO (con referencia concreta al código), PROPUESTO y PENDIENTE DE VALIDAR. No afirmes que hay reservas atómicas, historial de pagos ni entrevistas reales si no existe evidencia. No inventes cifras de mercado, resultados de pruebas ni requisitos de la universidad. Si el modelo actual guarda nombres y no referencias de piezas en pedidos, documenta esa limitación. Evita expandir el alcance hacia marketplace, pagos automáticos o transmisión.

Entrega un resumen con archivos creados, contradicciones encontradas, decisiones pendientes y recomendaciones para la semana 1. La documentación debe poder defenderla el estudiante y mantenerse consistente con el código; su utilidad prima sobre extensión.
